# Contributing to Foodly

Thanks for your interest in contributing to Foodly. This project is an open-source, mobile-first foodtech MVP focused on AI-assisted recipe generation, ingredient recognition, nutrition-aware filtering, and meal planning.

## Ways to Contribute

- Improve the product experience for people cooking at home.
- Add or refine recipe, nutrition, allergy-aware, and meal-planning features.
- Improve documentation and onboarding.
- Add tests for user-facing flows.
- Report bugs with clear reproduction steps.
- Suggest product improvements through GitHub issues.

## Before You Start

1. Check existing issues to avoid duplicate work.
2. For larger changes, open an issue first and describe the proposal.
3. Keep changes focused. Small, reviewable pull requests are easier to merge.
4. Follow the existing Rails and frontend patterns used in the project.

## Pull Request Guidelines

- Explain what changed and why.
- Include screenshots or short recordings for UI changes when useful.
- Add or update tests when the change affects behavior.
- Avoid unrelated refactors in the same pull request.
- Make sure the app still works for the main user flows: scan ingredients, generate recipes, save favorites, filter recipes, and plan meals.

## Product Principles

- Help users decide what to cook faster.
- Reduce food waste by using ingredients people already have.
- Respect allergies and dietary preferences.
- Keep the mobile experience simple enough to use from the kitchen.
- Prefer practical cooking guidance over abstract recipe search.

## Reporting Bugs

When opening a bug report, include:

- What you expected to happen.
- What actually happened.
- Steps to reproduce the issue.
- Screenshots, logs, or example inputs when relevant.
- Browser/device information for UI bugs.

## Security Issues

Please do not report security vulnerabilities in public issues. Follow the process in `SECURITY.md`.
